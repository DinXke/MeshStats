Hoe de weg over de broker werkt, en wat er niet langs kan

De server heeft geen weblogin voor de beheerpagina van deze node, maar de node publiceert zelf over MQTT — en dan is er wel degelijk een weg naartoe. De wijziging vertrekt als set <parameter> <waarde> op zijn cmd-topic. De node zoekt die parameter op in zijn eigen ingebakken tabel, toetst de waarde aan zijn eigen grenzen, zet hem en leest hem terug; wat hieronder als uitslag verschijnt is die teruglezing.

Wat hier niet langs kan. Alles wat de bereikbaarheid van de node kan afsnijden — zendvermogen, repeat, wie er mag inloggen — wordt over deze weg geweigerd, door de server én door de node zelf. De reden is wie er aan de overkant staat: bij de twee andere wegen is dat iemand met een wachtwoord, hier is het iedereen die de broker binnenlaat. Draait die op één gedeeld account, dan is dat elke node die eraan meepraat. Wil je zulke instellingen wél van hieraf kunnen zetten, vul dan MM_FW_NODE_USER en MM_FW_NODE_PASS in.

Er is geen antwoord op een publicatie, dus de uitslag komt terug in het eerstvolgende statistiekenbericht — dat de node meteen verstuurt. Reken op enkele seconden. Blijft het uit, dan is dat geen mislukking maar onzekerheid: een node op zonnestroom kan slapen.

Dat is ook de verstandige manier om een nieuwe monitorverbinding te toetsen.

Hoe de weg over de radio werkt

Deze repeater draait onze firmware niet en heeft geen IP-pad. Het schrijven gaat daarom niet naar hem toe maar naar zijn monitor {{ cfg_route.monitor }}: die staat op het lokale netwerk, krijgt de opdracht over HTTP, en zet set <parameter> <waarde> over LoRa. Daarna vraagt hij dezelfde parameter opnieuw op, en wat hieronder als uitslag verschijnt is die teruglezing — nooit wat de node op het zetten antwoordde. MeshCore zegt namelijk "OK" tegen dingen die het niet overgenomen heeft, en over de radio duurt het lang genoeg dat niemand het uit zichzelf natrekt.

Twee pakketten met een adempauze ertussen: reken op tien tot negentig seconden. Er loopt er één tegelijk, en tussen twee schrijfacties zit een minuut — laag gehouden met opzet, want de handeling die je na een misser meteen wilt doen is de omgekeerde.

De nieuwe firmware zit op de monitor en niet op deze repeater. Die krijgt twee doodgewone CLI-commando's binnen en hoeft niets te leren — dat is precies de reden dat deze weg bestaat.
